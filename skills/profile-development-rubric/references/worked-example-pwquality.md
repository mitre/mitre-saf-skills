# Worked example: pwquality `minlen` across `.conf` and `.conf.d/` drop-files

End-to-end walk through all five phases on a real drop-file check — STIG SV-274136 / SV-274139 on Amazon Linux 2023. This is the canonical pattern to mirror whenever a Linux config artifact lives in a main file plus a `*.conf.d/` directory.

Linked from [SKILL.md](../SKILL.md) — "The Five Phases of a Control Review" and the "drop-file directories" sub-section of Phase 2.

## Phase 1 — Read the source guidance end-to-end

Check text (paraphrased from the AL2023 STIG):

> Verify `minlen` is set in `/etc/security/pwquality.conf` *and* `/etc/security/pwquality.conf.d/*.conf`; if any file sets it below 15, this is a finding.

What to extract:
- **Target artifact:** the `minlen` key.
- **Locations:** both the main file AND the drop-file directory.
- **Expected value:** integer >= 15.
- **Input to generalize:** `min_password_length` (default `15`).
- **N/A conditions:** none called out.
- **N/R conditions:** none called out.
- **Empty case:** if no file sets `minlen` at all, the check fails ("not configured"). If files exist but none of them violate the threshold, the check passes vacuously. Classic pass-when-empty for the *violations* assertion, but NOT for the *configured-somewhere* assertion — that one must find at least one occurrence.

## Phase 2 — Pick the right InSpec resource

`parse_config_file` per file in a manually-built list. There is no typed pwquality resource that iterates drop-files for you; you build the file list yourself:

```ruby
files = ['/etc/security/pwquality.conf'] + Dir.glob('/etc/security/pwquality.conf.d/*.conf')
```

Anti-pattern: reading only the main file with `parse_config_file('/etc/security/pwquality.conf')`. Hardened systems use drop-files; misconfigured systems can override the main file via a drop-file. Both directions get misreported if you read only one path.

## Phase 3 — Frame the describe block

Headline: `"'minlen' across pwquality config"`. Two `it` blocks:

1. `'should be configured in at least one file'` — guards against silent absence.
2. `'should satisfy the threshold wherever it is set'` — the actual policy check.

## Phase 4 — Write the assertion

Find-the-outsiders: collect `values_found` (every place the key is set) and `invalid` (subset where the value is below threshold). Failure messages list searched paths AND offending `(path, value)` pairs.

```ruby
setting = 'minlen'
files = ['/etc/security/pwquality.conf'] + Dir.glob('/etc/security/pwquality.conf.d/*.conf')

values_found = files.flat_map do |path|
  next [] unless file(path).exist?
  parsed = parse_config_file(path).params
  parsed.key?(setting) ? [[path, parsed[setting]]] : []
end
invalid = values_found.reject { |_p, v| v.to_i >= input('min_password_length') }

describe "'#{setting}' across pwquality config" do
  it 'should be configured in at least one file' do
    expect(values_found).not_to be_empty,
      "'#{setting}' not configured. Searched:\n\t- #{files.join("\n\t- ")}"
  end
  it 'should satisfy the threshold wherever it is set' do
    expect(invalid).to be_empty,
      "Files with non-compliant '#{setting}':\n\t- #{invalid.map { |p, v| "#{p} (#{v})" }.join("\n\t- ")}"
  end
end
```

Two assertions in one describe — the report distinguishes "nobody set it" from "somebody set it wrong."

## Phase 5 — Gate with `only_if` / inputs

None for this control. No host/container distinction. No operator-declared bypass. Impact stays at the STIG-assigned severity.

## Phase 6 — Metadata

STIG `cci`, `nist`, `satisfies`, `severity` tags carry through unchanged from the source `desc` blocks.

## How to mirror this on another drop-file artifact

The exact same skeleton applies to any `/etc/X.conf` + `/etc/X.conf.d/*.conf` pair. Swap the `files = [...] + Dir.glob(...)` paths and the `setting` name. The "configured in at least one + valid wherever set" dual-it pattern is the load-bearing piece.

Resources that already iterate drop-files for you (no manual `Dir.glob` needed): `kernel_parameter` (sysctl drop-files across `/etc/sysctl.d/`, `/usr/lib/sysctl.d/`, `/run/sysctl.d/`), `sshd_config` / `sshd_active_config` (sshd_config.d), `limits_conf` (limits.d).

Everything else — pwquality, rsyslog, dnf/yum repos, profile.d, sudoers.d, modprobe.d, sssd conf.d — needs the manual file-list pattern shown above.
